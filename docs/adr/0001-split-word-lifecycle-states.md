# 拆分单词的三种生命周期状态：已记住 / 停用词 / 查无翻译

`isDeleted` 原本同时承载两层含义：用户手动点「移除单词」，以及后台翻译请求失败时系统自动打标。新需求又引入了第三层真正独立的用户意图——「停用词」（这个词根本不需要翻译，如 is、the），三者的触发方式（手动 vs 自动）、可逆性（用户随时可撤销 vs 系统冷却重试 vs 无撤销入口）和 UI 表现（立即弹面板 vs 出圆点 vs 完全静默）互不相同。我们没有把它们合并成一个枚举或继续复用单一布尔值，而是新增两个独立字段 `isIgnored`（停用词）、`isUntranslatable`（查无翻译，附 `lastAttemptAt` 冷却时间戳），`isDeleted` 语义收窄为「已记住」且行为保持不变。

历史数据不做重新分类：现有 `isDeleted=true` 的记录统一解释为「已记住」，因为原代码从未区分过两种成因，无法可靠地反推哪些词当初是自动删的。新字段对存量数据一律置 false。

高亮排除逻辑（页面不高亮已记住/停用词/查无翻译的词）在 JS 侧对三个字段取并集后再喂给 WASM matcher 的 `deleted` 集合，Rust 侧的 `find_deleted_matches` API 不需要感知三态区分。
